# trip-checklist-pdf Specification

## Purpose

Defines browser-native PDF/print output for a trip's packing checklist so the checklist can be shared or printed for manual use.

## Requirements

### Requirement: Trip detail SHALL expose a checklist print action

The system SHALL render an "匯出 PDF" button in the trip detail header. On desktop widths, the button SHALL occupy the trailing action position aligned with the trip title. On narrow screen widths, the button SHALL remain usable and SHALL follow the existing stacked trip-header layout.

#### Scenario: User sees the print action for an existing trip

- **WHEN** the user opens a valid trip detail view
- **THEN** the view shows the trip name and an "匯出 PDF" button in the trip header

---
### Requirement: The print action SHALL use the browser print flow

The system SHALL start the browser's native print flow when the user activates the "匯出 PDF" button. The action SHALL NOT download a binary PDF generated by the application and SHALL NOT require a third-party PDF generation dependency.

#### Scenario: User starts PDF creation

- **WHEN** the user activates "匯出 PDF"
- **THEN** the browser print flow opens so the user can print or choose "Save as PDF"

---
### Requirement: The printable manifest SHALL contain the trip checklist fields

The print output SHALL show the trip name followed by the trip items in their current order. Each item row SHALL contain exactly these fields in order: item name, quantity, departure blank checkbox, and return blank checkbox.

#### Scenario: A trip with multiple items is printed

- **GIVEN** the trip name is "11月日本土浦煙火行" and its ordered items are "護照" with quantity 1 and "手機" with quantity 1
- **WHEN** the user opens the print preview
- **THEN** the preview contains the trip name and rows in this order: "護照 | 1 | blank box | blank box", then "手機 | 1 | blank box | blank box"

---
### Requirement: Printable checkboxes SHALL always be blank

The print output SHALL render an empty departure checkbox and an empty return checkbox for every item. The rendered checkbox state SHALL NOT depend on departureChecked or returnChecked in the trip state.

#### Scenario: Existing checked state is excluded from the print output

- **GIVEN** the "護照" item has departureChecked set to true and returnChecked set to true in the interactive trip view
- **WHEN** the user opens the print preview
- **THEN** the "護照" row contains two empty checkboxes and neither checkbox is marked as checked

##### Example: Checked interactive item produces a fresh paper checklist

- **GIVEN** item: name="護照", quantity=1, departureChecked=true, returnChecked=false
- **WHEN** the print manifest is generated
- **THEN** the row output is "護照 | 1 | ☐ | ☐"

---
### Requirement: Print output SHALL exclude interactive controls

The print output SHALL hide the return-trip link, application header decoration, item-entry form, interactive checkbox inputs, and edit/delete action column. The print output SHALL retain the manifest heading, table header, item rows, and blank checkbox visuals.

#### Scenario: Print preview contains only checklist content

- **WHEN** the user opens the print preview for a trip with items
- **THEN** the preview does not show navigation, item-entry controls, interactive inputs, or edit/delete buttons

##### Example: Interactive controls are hidden

- **GIVEN** the trip "11月日本土浦煙火行" has two items and the screen shows the add-item form plus edit and delete buttons
- **WHEN** the user opens the print preview
- **THEN** the preview shows the trip title and four checklist columns, while the add-item form and edit/delete controls are absent

---
### Requirement: Printing SHALL NOT modify trip data

Opening or cancelling the browser print flow SHALL NOT change the trip object, item quantities, item names, departureChecked values, returnChecked values, or localStorage data.

#### Scenario: User cancels printing

- **GIVEN** a trip contains an item with departureChecked=true and returnChecked=false
- **WHEN** the user activates "匯出 PDF" and cancels the print dialog
- **THEN** the trip data and both checkbox values remain unchanged

---
### Requirement: An empty trip SHALL have a printable empty state

When the current trip contains no items, the print output SHALL show the trip name and a clear empty-list message. The output SHALL NOT show the item-entry form or interactive controls.

#### Scenario: User prints a trip without items

- **GIVEN** the current trip has no items
- **WHEN** the user opens the print preview
- **THEN** the preview shows the trip name and an empty-list message without an item-entry form

---
### Requirement: Long manifests SHALL remain printable across pages

The print stylesheet SHALL support multiple pages for long item lists, repeat the table header on subsequent pages, preserve readable margins, and avoid splitting a single item row between pages when the browser supports the relevant print CSS.

#### Scenario: A long item list is printed

- **GIVEN** a trip contains enough items to exceed one printed page
- **WHEN** the user opens the print preview
- **THEN** all item rows remain available across pages and the table header is repeated on subsequent pages
