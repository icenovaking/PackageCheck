## Context

旅程明細與旅程類型設定都由 `app.js` 產生表格標記，`style.css` 則在桌機、768 px、540 px 與 380 px 等條件下調整欄寬與控制尺寸。現況有三個互相影響的問題：勾勾以固定 margin 位移、數量使用原生 number input、編輯狀態將動作儲存格本身改成 flex 且沒有完整共用一般狀態的圖示尺寸規則。

本變更須維持既有 localStorage 中的正整數數量、JSON 匯入／匯出格式、表格資訊架構與旅遊主題視覺。主要使用情境同時包含手機觸控及桌機滑鼠／鍵盤。

## Goals / Non-Goals

**Goals:**

- 讓已勾選圖示在所有支援 viewport 中相對於方框水平及垂直置中。
- 讓新增、編輯旅程物品及新增、編輯預設物品的常用數量可直接從 1 至 10 選取。
- 保留既有或匯入後大於 10 的正整數數量，且編輯名稱後儲存不得意外改值。
- 讓編輯／刪除與儲存／取消動作在相同儲存格位置使用一致的視覺尺寸、圖示尺寸、間距及可操作區域。
- 使用同一份語意標記與響應式樣式服務 320 px 手機到桌機，不建立裝置專屬分支。

**Non-Goals:**

- 不變更 localStorage schema、資料匯入／匯出版本或既有數量欄位型別。
- 不提供任意新數量大於 10 的輸入介面；大於 10 僅作為既有資料相容值。
- 不加入加減 stepper、底部抽屜、對話框或獨立手機版物品卡片。
- 不改變勾選後立即持久化、刪除確認或重複名稱驗證行為。
- 不重設整體視覺主題、字體或色彩 token。

## Decisions

### 共用數量選項產生器與原生 select

在 `app.js` 建立單一數量選項產生邏輯，供旅程新增表單、旅程物品編輯列、預設物品新增表單及預設物品編輯列使用。一般情況產生 1 至 10，預設選取 1；編輯既有數量時，若目前值是大於 10 的正整數，額外加入該數值並選取，確保只改名稱後儲存仍保留原值。

提交時仍以十進位正整數解析並驗證。正常 UI 只會產生 1 至 10 或目前既有的大於 10 值；若 DOM 被竄改成零、負數、非數字或非現有選項，既有錯誤處理 SHALL 阻止儲存。

選擇原生 select 是因為手機可使用系統選擇器而不開啟鍵盤，桌機則保留標準鍵盤與滑鼠操作。未採用三段式 stepper，因為兩個動作按鈕加數值會在窄欄位造成擁擠。

### 勾勾以容器中心而非 margin 定位

保留既有 checkbox input、label 與視覺方框語意，但移除勾勾的固定 margin 位移。視覺方框提供置中定位上下文，勾勾使用中心座標與相對比例繪製；手機只調整外框與圖示 token，不另外覆寫偏移座標。

觸控 label 與可見方框分離：可見方框維持與目前視覺相近的尺寸，label 在 coarse pointer 環境提供至少 44 px 的命中範圍。鍵盤 focus-visible 狀態仍套用在可見方框上。

### 動作儲存格維持 table-cell 並共用 action group

一般與編輯狀態的動作儲存格都維持原生 table-cell 排版。按鈕排列由儲存格內的共用 action group 容器負責，禁止將 `td` 本身改成 flex。編輯／刪除與儲存／取消使用同一組按鈕外框、圖示尺寸、gap、focus 及 coarse-pointer 命中區 token，只有色彩與 aria-label 依動作改變。

此結構可避免編輯狀態脫離 table layout，也讓兩種狀態在切換前後保留相同欄位中心與按鈕基線。

### 內容驅動的響應式尺寸與欄寬

表格保留同一組五欄語意。窄 viewport 以 CSS custom properties、百分比欄寬、`clamp()` 與 pointer media query 調整視覺尺寸；44 px 是觸控可用性的下限，不是針對某一手機型號的固定版面。桌機沿用既有較寬欄位與舒適間距。

數量 select 在窄欄位置中並使用至少 16 px 字級，避免 iOS Safari 聚焦時自動縮放。320 px、390 px 與桌機寬度都不得產生頁面或物品表格水平捲動。

## Implementation Contract

**Observable behavior**

- 四個數量入口顯示原生 select，選項 1 至 10，新增時預設為 1。
- 編輯數量 12 的既有物品或預設物品時，select 顯示並選取 12；只修改名稱並儲存後數量仍為 12。
- 使用者可將既有 12 改選為 1 至 10；一旦改為範圍內數值，介面不提供再次輸入任意大於 10 新值的方式。
- 出發與回程 checkbox 的已勾選圖示在未勾選方框相同的幾何中心顯示。
- 進入編輯狀態時，儲存／取消按鈕取代編輯／刪除按鈕，但按鈕外框、圖示比例、間距及動作欄對齊不跳動。
- 所有既有勾選、儲存、取消、刪除與鍵盤 focus 行為保持可用。

**Interface and data shape**

- `qty` 仍為正整數，不新增欄位，不提高資料匯出版本。
- 現有 JS selector hook 可維持名稱，或在同一行為範圍內改為 quantity-select 專用 class；所有讀值端必須從 select 的 value 取得十進位整數。
- 數量選項產生器接受目前數量並輸出 1 至 10，加上最多一個目前既有且大於 10 的選項。
- 動作按鈕的事件 hook 與 aria-label 必須保留，避免改變持久化與可及性契約。

**Failure modes**

- 非正整數、零、負數或不在目前渲染選項中的竄改值不得寫入 state。
- 既有大於 10 的正整數不得在 render、只改名稱後儲存、匯出或重新載入時被截斷為 10。
- 若 CSS 功能查詢或 pointer media query 不匹配，控制仍須以基本樣式可見、可聚焦及可操作。

**Acceptance criteria**

- Node 測試覆蓋 1、10、既有 11 以上、非法竄改值，以及旅程物品與預設物品的新增／編輯路徑。
- 在專案根目錄執行 `node --test tests/trip-data-portability.test.js` 全部通過。
- 以 320 px、390 px 及至少 1024 px viewport 檢查未勾選／已勾選、一般／編輯狀態，物品表格沒有水平溢位。
- 在 coarse pointer 條件下，checkbox 與四種 row action 都有至少 44 px 的可點擊範圍；在 keyboard 操作下 select、checkbox 與按鈕都有可見 focus。
- 手機聚焦數量 select 時使用原生選擇器而非數字鍵盤。

**Scope boundaries**

- In scope: `app.js` 的數量控制標記與共用選項邏輯、物品／預設物品編輯動作標記、`style.css` 的 checkbox、select、action group 與響應式規則、既有 Node 測試。
- Out of scope: 資料遷移、匯入格式變更、列印清單欄位、常用物品資料模型、其他頁面的整體重排。

## Risks / Trade-offs

- [Risk] 320 px 內同時容納名稱、數量、兩個 checkbox 與兩個動作按鈕時名稱欄變窄 → 允許物品名稱自然換行，並以內容驅動欄寬驗證無水平溢位。
- [Risk] select 在 Safari、Chrome 與桌機瀏覽器的原生箭頭外觀不同 → 只統一尺寸、字級、邊框與對齊，不依賴像素完全相同的瀏覽器原生 glyph。
- [Risk] 動態加入既有大於 10 選項可能被誤解為允許建立任意大數量 → 僅在 edit render 接收既有值時加入，不在新增表單提供。
- [Risk] 44 px 命中區放大後擠壓相鄰控制 → 使用欄寬與內部 action group 協調空間，驗證相鄰命中區不重疊。
