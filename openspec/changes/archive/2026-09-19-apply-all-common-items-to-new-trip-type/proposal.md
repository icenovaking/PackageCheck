## Why

目前建立旅程類型後，使用者必須逐一把常用物品加入預設清單；當常用物品較多時，重複操作比先全部加入再刪除不需要的項目更耗時。新增預設勾選的一鍵套用選項，可讓旅程類型更快進入可用狀態，同時保留建立空白類型的選擇。

## What Changes

- 在「新增類型」表單的類型名稱與主要送出按鈕之間，加入「將全部常用物品加入此類型」勾選選項，預設為勾選。
- 勾選時，建立類型會把送出當下的所有常用物品一次複製為該類型的預設物品，每項數量為 1，並各自產生預設物品 ID。
- 取消勾選時，維持現有行為，建立不含預設物品的類型。
- 沒有常用物品時，選項保持可見但停用，並以文字說明目前沒有可套用的常用物品；建立類型仍可正常完成。
- 套用採一次性複製，不建立常用物品與預設物品之間的持續關聯；日後新增、改名或刪除常用物品不會修改既有類型。
- 讓整個選項列可點擊，並在手機寬度維持至少 44 px 的觸控範圍，不造成水平捲動。

## Capabilities

### New Capabilities

無。

### Modified Capabilities

- `trip-type-presets`: 擴充建立旅程類型的行為，使其可依預設勾選選項一次建立全部常用物品的預設副本。
- `common-item-settings`: 擴充常用物品的一次性複製行為，涵蓋建立類型時的批次套用、空目錄狀態與後續互不連動。
- `responsive-layout`: 明定新增類型表單中的批次套用選項在手機上的觸控範圍與無水平溢位要求。

## Impact

- `app.js`: 新增類型表單標記、選項狀態與送出時的批次複製邏輯。
- `style.css`: 新增符合現有表單視覺語言的選項列與響應式、鍵盤焦點樣式。
- `tests/`: 增加建立類型時預設套用、取消套用、空常用物品與一次性複製邊界的回歸驗證。
- 不變更既有資料格式、匯入匯出版本、外部 API 或執行期依賴。
